# 路线图

以下内容只是候选方向，不是当前能力或交付承诺。

当前第一版之后的轻量搜索质量升级，按可独立交付的批次记录在
[第二版搜索质量升级计划](v2-search-quality-plan.md)。该计划优先改善现有 Bing 和
DuckDuckGo 的结果质量，不以增加搜索引擎数量为目标。

## v1.1：官方设置体验

- 继续使用 DSH 公开 Config Schema、Client slot 和 settings API；
- 改善字段本地化与 provider 状态提示；
- 不自建 HTTP bridge，不处理凭据；
- UI 只表达现有有限配置和安全撤销流程。

## v1.2：第三个搜索来源

- 优先评估用户自建 SearXNG；
- 自定义 endpoint 引入新的 SSRF 和凭据边界，必须先完成独立威胁模型；
- 在协议、host、IP、逐跳重定向和 DNS rebinding 防护完成前不实现。

## v1.3：隐私和可靠性增强

- 允许用户显式选择是否向备用引擎发送同一查询；
- 评估仅内存的短期缓存；
- 增加不包含查询正文的本地诊断；
- 提供只在开发阶段运行的 fixture 更新工具，不在安装时联网。

## v2：附加搜索工具

- 分别评估平台搜索、多源交叉验证和时间过滤；
- 每项作为独立工具和独立权限审查；
- 付费引擎、凭据管理和匿名 MCP 服务必须显式 opt-in。

## 独立项目：安全网页抓取

`web_fetch` 不属于本插件第一版。如果未来需要，应作为独立插件或独立高风险模块设计，并先解决 SSRF、重定向、DNS rebinding、内网和云元数据地址、响应大小、内容类型及提示注入。启动无沙箱浏览器不是可接受的默认方案。
